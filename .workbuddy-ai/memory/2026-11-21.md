## brawl-draft-app：荒野乱斗排位 BP 助手（四阶段全部完成）

从零构建 Vite + React 18 + TS(strict) + Tailwind 3.4 + Vitest + Capacitor 6 的安卓小窗 BP 辅助 App。
用户需求文档见对话首条长文本；本文件只记录**有长期价值的决策与结论**。

### Schema v2 实测结论（与需求文档不一致，代码按实测实现）
1. **1v1 克制矩阵不在 mode 顶层**，嵌在 `modes[].brawlers[].matchups[]`，字段 `opponent_id / games / win_rate / smoothed_wr`。
   `metaIndex.ts` 展平为 `Map<mode, Map<selfId, Map<oppId, wr>>>`。矩阵完全对称（bounty 816 条边，反向全存在）。
2. `brawlers` 是**数组** `[{id,name}]`（108 条），不是字典；`roles[].brawler_ids` **全为空数组**，角色只能按英文名匹配。
   roles 写 `"Larry & Laurie"`、字典写 `"LARRY & LAWRIE"` → `ROLE_NAME_ALIAS` 修正。
3. 地图层仅覆盖 63~89 英雄，模式层 94~106 → 候选集以地图层为准。
4. 顶层键：`schema_version(2) / updated_at / season_start / total_battles(5746) / min_tier(20) / params / brawlers / maps(24) / modes(6) / roles`。
5. `pick_order` 取值：`FIRST | MIDDLE | LAST`；`score` 为图内归一化 0~100（第一名=100）。

### 算分引擎关键设计
- Ban 分 = score×60% + 归一化热度×25% + FIRST×15%，breakdown 三项贡献相加严格等于总分。
- Pick 分 = 加权归一化（基础 50% / 克制 35%×(亮牌数/3)×(后手1.35) / 阵容 15%）+ 顺位修正。
- 详情面板显示**归一化后权重**（合计 100%），否则 50+23+15=88% 与贡献分对不上。
- 敌方槽位录入：排序改为强度70%+热度30%，标签措辞「克制我方 X」；切回我方恢复克制计算。
- 3v3 蛇形序列：A1 → B1 → B2 → A2 → A3 → B3。

### 踩过的坑（同类项目可复用）
- `matchScore` 曾用 0 表示「完全匹配」，与调用方 `>0` 过滤冲突 → 精确搜索被误杀。
- `normalizeName` 会删光中文得到空串，`startsWith('')` 恒 true → 纯中文查询命中全部英雄。修法：`if (qn)` 守卫英文分支。
- 280px 下 3+3 个固定 44px 槽位溢出被裁 → 改 `flex-1 + aspect-square + max-w-[46px]` 弹性尺寸（280→41px，320→46px）。
- `h-[100dvh]` 在老 WebView 不支持会塌陷 → CSS 双写 `height:100vh; height:100dvh`。
- `cap sync` 只拷 dist，改代码后必须先 build。

## 追加：Ban/Pick 权重分离 + 修 hasData 未传递的 bug

**Bug**：`pickRecommendations` 里 `evaluatePick(idx, state, stat, position, 'ally')` 漏传 hasData，
导致无数据英雄 hasData 恒为 true → UI 显示 50 分而不是「—」，且排序把 50 分排在真实数据前面。
用户截图看到「一堆 50 分英雄」就是这个原因。已修（传参 + 排序 hasData 优先）。

**Ban / Pick 两套独立权重**（用户要求）：
- Ban：出场率 50% + 地图强度 35% + 先手优先级 15%（热门 = 会被抢，Ban 收益大）
- Pick：对位克制 40% + 本图胜率 25% + 地图强度 25% + 阵容结构 10%
- 敌方录入：地图强度 70% + 出场率 30%（只求快速定位）

**新增胜率置信度收缩**：`confidence = min(1, games/50)`，胜率向 50% 收缩后再算分。
原因：琥珀 10 场 58% 会排第一（用户明确说过这是样本噪音）。收缩后 P先生(42场56%) 升到第一，
阿方(4场) 从 54.5 掉到 47.9，斯图(1场) 掉出前 6。

**实测对比**（Shooting Star）：
- Ban 前 6：佩佩 85 / 布洛克 66 / 麦克斯 55 / 纳尼 50 / 斯派克 47 / 曼迪 45
- Pick 前 6：P先生 55 / 琥珀 54 / 贝尔 52 / 娜吉亚 50 / 阿方 48 / 皮尔斯 46
两套排序完全不同，符合「Ban 看谁会被选，Pick 看谁能赢」。

详情面板 Pick 分支改为四项：对位克制 / 本图胜率 / 地图强度 / 阵容结构。
测试 49 项全过（更新了 4 条硬编码权重的断言，改为验证权重和为 1 与行为关系）。

## 追加：胜率置信度改为「剔除权重」而非「收缩数值」

用户指出琥珀在这图根本没人拿，且它当过一个月「限时满级英雄」，出场率被人为抬高。
要求更严格。

**关键修正**：原来把低置信胜率按 50 分计入权重，等于让不可信的项占住权重、
把所有人拉平到 50 附近。改为 `wrWeight = W_PICK_WR * confidence`，置信度为 0 时该项
**完全不参与加权**（totalWeight 也随之缩小）。

参数：`WR_MIN_SAMPLE = 30`（低于此置信度 0）、`WR_FULL_SAMPLE = 120`（达到才全信）。
两个常量在 draftEngine.ts 常量区，等后端数据量上来后调整。

效果（Shooting Star，ban 掉 6 个后）：
- 之前：琥珀第 1（50.2）
- 现在：P先生 50.0 / 娜吉亚 49.3 / 贝尔 46.7 / 皮尔斯 45.8 / **琥珀 45.3（第 5）**

详情 reasons 新增：样本 <30 场提示「胜率不参与计算」，30~120 场提示「按 X% 折算」。

**待办（用户）**：再从后端抓更多对局数据，届时重新评估 WR_MIN_SAMPLE / WR_FULL_SAMPLE。
另外「限时满级英雄」污染的是 use_rate（出场率），会直接影响 Ban 分，前端无法识别，
需要后端剔除试用期数据。

## 追加：界面密度（舒适 / 紧凑）适配

`src/index.css` 的 `:root` 定义触控尺寸变量，`[data-density='compact']` 覆盖：
`--tap 44/34`、`--tap-sm 34/28`、`--chip-h 26/20`、`--row-h 52/46`、`--avatar 38/34`、`--font-name 14/13`。
根节点 `data-density` + localStorage `brawl.ui.density` 持久化；下拉 26px 收起、上拉展开（TopBar 触摸手势）。

本轮把变量接到各处：
- 筛选 chip：`inline-flex h-[var(--chip-h)] items-center`（原来 py-0.5+leading-4 固定 20px）
- 搜索框：`h-[var(--tap-sm)]`
- 列表行：`h-[var(--row-h)]` + `Avatar size="var(--avatar)"` + `text-[length:var(--font-name)]`
- DraftBar：Ban 槽 `max-w-[var(--tap-sm)]`、撤回/重做/清空 `h-[var(--tap-sm)] w-[calc(var(--tap-sm)*0.72)]`、6 个主槽 `max-w-[calc(var(--tap)_+_4px)]`

**关键坑 1**：`Avatar` 的 `size` 原本是 number，传 CSS 变量必须放宽为 `number | string`，
兜底首字字号改成 `calc(${size} * 0.42)`。Tailwind 里字号用变量要写 `text-[length:var(--font-name)]`，
写 `text-[var(--font-name)]` 会被当成颜色。
**关键坑 2**：Tailwind 任意值里 `calc(var(--tap)+4px)` 是**无效 CSS**（+/- 必须有空格），
要写 `calc(var(--tap)_+_4px)`（下划线转空格）。
**关键坑 3**：`.safe-bottom`/`.safe-top` 与 `pb-2`/`pt-1.5` 都是 padding，后写的 utility 覆盖前者 →
底栏/顶栏的常规内边距被吃掉（slot 贴死窗口底边）。已在 DraftBar 改为
`pb-[max(8px,env(safe-area-inset-bottom,0px))]`。**TopBar / MapPicker / BrawlerDetail 仍有此问题**（未修）。
**关键坑 4**：TopBar 手势的 startY 原用 useState，touchstart→touchend 若同帧完成会读到 null 直接 return；
改 useRef 后正常（合成事件测试也过）。

## 追加：拖拽失灵修复 + 默认展开 + 列表改头像网格

**拖拽「不灵敏/基本不能拖」的三个原因**（实测定位，Chromium 触摸事件本身是正常的）：
1. 拖拽条只有 18px 高、可见横条 4px，小窗里手指根本压不中；
2. 触发规则是「高度过半」（122→222 要拖 50px 以上），短拖一律回弹；
3. `setPointerCapture` 在部分 WebView 上不稳，手指离开元素就断。

**改法**：拖拽条 18→24px、横条 4→6px 宽 48px、拖动时变天蓝色；判定改成**只认方向**——
位移超 14px 死区后，向上拖就展开、向下拖就收起（不再看高度过半）；监听改挂 `window` 的
pointermove/pointerup，不用 setPointerCapture。实测 20px 下拖即收起、16px 上拖即展开。

**默认态改展开**：`localStorage.getItem('brawl.ui.panel') !== 'collapsed'`，即没手动收起过就展开。

**展开态槽位改「纯头像」**：2 列 × 3 行、148×52 的格子，蓝/红底色（ally/15、enemy/15），
头像 52px 居中不裁切，序号做成 `bg-black/45` 小胶囊常驻在靠中间的角（我方左下、敌方右下，抄参考工具）。
**踩坑**：148×52 是 2.85:1，`object-cover` 会把方头像裁成一条眼睛鼻子（试过 center 和 28% 位置都难看），
`object-contain` 又会两侧空 96px。最终选 contain 居中 + 序号胶囊——宁可留白也不要裁脸。

**列表从「一英雄一行」改成 5 列头像网格**（`BrawlerTile.tsx` 取代已删除的 `BrawlerRow.tsx`）：
单格 56×83 = 头像 56（左上角压「先手/C位」角标）+ 名字 9px + 分数 11px。
108 个英雄的滚动高度从 5616px 降到 2025px（2.8 倍密度），320 宽下列表区能看到 2 行 × 5 = 10 个。
